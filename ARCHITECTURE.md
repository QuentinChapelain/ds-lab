# Architecture

La carte du dépôt, limitée à ce qui change rarement. Les valeurs se lisent dans `tokens/commun/` et dans le dossier de chaque marque, les règles dans `docs/regles.md`, les décisions dans `docs/decisions.md`, les identifiants de règles cités par les sorties dans `docs/identifiants.md`, la dette à payer dans `KNOWN_ISSUES.md`, ce qui manque au design system dans `docs/feuille-de-route.md`. Tout chemin cité dans la documentation s'écrit depuis la racine du dépôt ; `test/derive-docs.test.js` vérifie qu'il existe.

## Schéma d'ensemble

```
Migration d'un site existant (phases 2 et 3 du README)

  page servie ──► audit ───────────► reduce ──────────────────► apply ───────► verify
                  déclaré et rendu    table ancien → nouveau     copie du site   pixels et arbre
                  src/declared/       src/reduce/  src/brand/    src/apply/      d'accessibilité
                  src/rendered/       simulation : src/browser/                  src/verify/
                  src/browser/        revue, consigne : src/report/   │                ▲
                                                                      └► ajout ────────┘ verify --ajout
                                                          feuilles ajoutées, site intact (D37, D38)
                                                          src/apply/ajout.js, src/browser/ordre.js
                                                          verdict par ligne décidée (D39) :
                                                          src/verify/arrivee.js

Constat des composants d'un site (D46)

  pages servies ──► relevé au repos ───────────────► releve.json ──► constat ──────────► constat.json, .md, .html
  une origine       arbre d'accessibilité, Tab,       captures         types, versions,     captures
                    mesures, captures                    ▲              gabarit, blocs,
                    src/browser/composants.js            │              scores, décisions
                    table de signatures facultative      │              src/composants/, src/report/constat.js
                    (config/signatures/)                 └── --releve : recalcul sans navigateur

Jetons d'une marque (phase 1)

  entree.json ──► npm run saisie ──► échelles générées ──┐
                  refus avec motif                       ▼
  primitives ──────────────────────────────────────► marque ──► sémantique (rôles) ──► paires
       └───────────────────────── src/tokens/ ──────────┴──────────────────────────────┘
                     réunis par marque.resolver.json : jeux, contextes mode et largeur
                                      │
               ┌──────────────────────┴───────────────────────┐
         contrôles, sortie 0, 1 ou 2                   planches HTML
         npm run contraste                             src/report/roles.js
         npm run espacements                           src/report/espacements.js
         npm run typo                                  src/report/typo.js

         feuille CSS de la marque, tous contextes : npm run css, src/tokens/css.js, par Terrazzo (D36)
         tokens/<marque>/jetons.css

         thèmes Vuetify clair et sombre, par la table tokens/commun/vuetify.json :
         npm run vuetify, src/tokens/vuetify.js (D41) ; tokens/<marque>/vuetify.json
                                      │
         atelier des composants, Storybook 10 et Vuetify 4 : atelier/, son package.json et son verrou (D42)
         enveloppes, chacune un menu et son rendu sur la fabrique commune (D51), variables ds- du thème :
         bouton (D43), champ de texte (D49), carte (D50), bouton à icône sur le bouton (D52),
         avatar (D54), étiquette (D55) dans atelier/composants/ ; icônes : chemins de @mdi/js par
         atelier/composants/icone.js ; initiales de l'avatar : atelier/composants/initiales.js
                                      │
         modules, sur la même fabrique, sans pièce de Vuetify, style de mise en page seulement (D61) :
         MemberCard et MemberList dans atelier/modules/ ; dix membres fictifs : atelier/stories/membres.js
                                      │
         fiches des composants et des modules : docs/composants/ et docs/modules/, en-tête et blocs écrits par
         npm --prefix atelier run fiches (atelier/fiches.js, D56, D61), noms tirés de atelier/composants/noms.json (D57)
```

Chaque commande npm a son point d'entrée dans `src/cli/`, sauf `npm run demo` (`test/helpers/demo.js`), `npm run types` (`tsc`), `npm run knip` (`knip`), `npm run dependances` (`depcruise`), `npm run style` (`stylelint`) et `npm test` (`node --test`). L'orchestration de l'audit et de la réduction vit dans leur couche, `src/audit/run.js` et `src/reduce/run.js` (D30) ; aucun module de `src/` hors de `src/cli/` n'importe de `src/cli/`. Toute commande a trois issues (D18) : 0 tout passe, 1 l'entrée a été lue et jugée (règle en échec, marque refusée avec son motif), 2 l'entrée n'a pas pu être jugée (fichier absent ou illisible, option inconnue, panne), message d'une ligne préfixé par le nom de la commande ; la garde commune est `src/cli/garde.js`. Exception : `src/cli/login.js` exporte `saveState` et `readState`, lus par `test/login.test.js`, logique restée dans un point d'entrée ; `test/couches.test.js` ne garde que `src/cli/reduce.js`. Les sorties d'audit et de réduction sur un vrai site vont dans `local/`, jamais versionné.

## src/, un dossier par ligne

| Dossier | Rôle |
|---|---|
| `src/cli/` | Points d'entrée : un fichier par commande npm, sauf `demo`, `types` et `test`, plus les générateurs de jetons et de planches, et deux commandes posées dans le dépôt d'une équipe, `relecteur.js` et `carnet.js` (D67, D71) ; `garde.js`, lancement commun et codes de sortie (D18), et `parMarque`, un contrôle sur une marque ou sur chacune (D26), `marquesDe`, les marques de `--marques` (D66) ; `version.js`, garde de version (D40) |
| `src/banc/` | Banc d'essai (D67) : pose du dossier d'un passage hors du dépôt, copie de l'arbre de ds-lab sans les chemins cachés (`fixtures/banc/exercices.json`) et sans historique, commits à auteur et date fixes, réglages sans chemin vers le vrai dépôt (D70), `TMPDIR` dans le passage, posé par la commande de lancement (D71), dossier du journal de Claude Code (`banc.js`) ; point de départ de chaque exercice, une base et des couches (`departs.js`, D68) ; planches d'une app (`planches.js`) ; ce qu'un passage a posé, lu dans ses fichiers, et les trois origines d'un écart au catalogue (`releve.js`) ; ce que sa session a lu, d'après son journal (`lectures.js`, D69) ; un inventaire face à sa liste de référence (`inventaire.js`, D69) ; la session qui porte le brief et ses heures, ce qu'elle a écrit et comment, le journal du relecteur et ses pannes, les heures du carnet face aux appels qui le nomment, ce qu'elle a chargé face à la pose (`traces.js`, D71) ; outils (`outils.js`) ; le relevé est dans `src/cli/banc.js` |
| `src/audit/` | Orchestration d'un audit (navigateur, une session par hôte, pages, rapports) ; exécution facultative du script v1 |
| `src/browser/` | Ce qui tourne dans le navigateur : lancement de Chromium (`lancement.js`, D34), chargement, feuilles de style dans l'ordre de la cascade (`sheets.js`, D33), relevé du rendu, états forcés, simulation d'une table ; règle gagnante d'une propriété, élément par élément, pour les feuilles ajoutées (`ordre.js`, D37) ; relevé des pièces d'interface au repos : rôle et nom calculés par l'arbre d'accessibilité, suite de la touche Tab, zone de clic, mesures, captures (`composants.js`, D46) |
| `src/composants/` | Constat des composants, sans navigateur (D46) : type, origine, version, apparence, accessibilité de base et gabarit (`pieces.js`), blocs non identifiés (`blocs.js`), décisions du designer (`decisions.js`), scores (`scores.js`), constat et lignes à capturer (`constat.js`), guidage : phrase courte, ce qu'il reste à faire, éléments à remplacer, défauts et différences des versions, ordre des fiches et données des graphiques (`guidage.js`, D47, D48) ; orchestration de `npm run composants` et recalcul depuis un relevé (`run.js`) |
| `src/declared/` | Audit du déclaré : toutes les feuilles de toutes les pages, dédoublonnées et comptées |
| `src/rendered/` | Audit du rendu : relevé d'une page chargée, puis agrégation de toutes les pages |
| `src/lib/` | Fonctions pures partagées : couleurs (OKLab, ΔE, contraste WCAG), mise en forme des sorties (`format.js`), unités, clés de valeurs, adresses, sources ; lecture d'un fichier JSON et message d'erreur d'une ligne (`fichiers.js`, D30) ; ligne d'une clé de simulation (`cles.js`, D39) ; nom de la variable CSS d'un jeton (`nom-css.js`, D62) |
| `src/reduce/` | Proposition de la table ancien → nouveau, texte sur plein et couplages, déclarations sources et conflits ; orchestration de `npm run reduce` (`run.js`, `runReduce`, D30) |
| `src/brand/` | Marque déclarée dans la cible ; lecture rapide de la marque d'un site, avant la réduction |
| `src/polices/` | Police des titres d'une marque : lecture d'un WOFF2 (mesures, graisses, licence, couverture), sans dépendance ; garde-fous ; contrôle d'encre de deux lignes dans Chromium (`encre.js`, playwright-core déjà présent), lancé par la saisie quand l'entrée donne les fichiers |
| `src/valise/` | Générateur d'échelles visé par contraste, et son contrôle `checkValise` |
| `src/tokens/` | Jetons DTCG d'une marque : lecteur de resolver, liste des marques (`dossiersDeMarque`, `nomDeMarque`), primitives, pleins, rôles et paires, espacements, styles de texte ; calcul des trois contrôles de la cible (contraste, espacements, typo) ; écriture de la saisie, à côté puis en remplacement (`ecriture.js`, D31) ; feuille CSS complète d'une marque, écrite par Terrazzo depuis son resolver et comparée au lecteur avant écriture (`css.js`, D36) ; thèmes Vuetify clair et sombre d'une marque, par la table commune, chaque fond avec son texte (`vuetify.js`, D41) ; cible d'une réduction prise dans la marque : ses échelles en clair, le neutre, l'erreur et le succès, le texte sur chaque plein, les dimensions de la cible donnée, et les échelles de la marque, seules comparées par M8 (`cible.js`, D76, D82) |
| `src/report/` | Sorties lisibles : rapport d'audit, revue, `migration.md`, planches des rôles, des espacements et de la typo d'une marque (`planche(dossier)`), calibrage des pleins ; consigne pour un agent, structurée (`consigne.js`, D29), et `modifications.json` (`modifications.js`) ; texte du contrôle de contraste (`contraste.js`) ; constat des composants en JSON, Markdown et HTML (`constat.js`), ses textes affichés dans un fichier de données (`constat.textes.json`, lu par `textes.js`, D46), couleurs des rôles neutres communs en clair et en sombre (D47) ; anneau des origines, barres des scores, sommaire des versions et fiches repliées, en SVG écrit par le rendu (D48) ; textes du skill, générés depuis `docs/regles.md` et `docs/techniques/` (`skill.js`, D66) ; lignes de `verifier`, une par échec, avec le numéro de sa règle et ce qu'il faut faire (`verifier.js`, D66) |
| `src/apply/` | Application de `modifications.json` aux feuilles d'une copie du site, et feuilles ajoutées qui la posent à côté de l'ancien code, sur le site intact (`ajout.js`, D37) ; localisation d'une entrée et garde de sa valeur écrite, partagées par les deux (`localisation.js`) ; lit le fichier, n'importe rien de `src/reduce/` ni de `src/report/` (D30) |
| `src/verify/` | Captures, références et comparaisons (pixels, arbre d'accessibilité), partagées par reduce et verify ; feuilles ajoutées posées sur la page avant une capture, avec le media du lien, à la fenêtre du manifeste (`poserAjouts`, `capturePage`, D37) ; verdict par ligne décidée : simulation de la réduction rejouée sans être allumée, relevée avant puis après la pose dans le même chargement, hauteurs, canal de ce qui n'arrive pas, jugement des pages vérifiées (`arrivee.js`, D39) |
| `src/parcours/` | Le parcours (D72) : lecture et contrôle de `projet.json` (`projet.js`), état calculé depuis les sorties du projet, six étapes en quatre temps, moment, écran gardé, bilan, choix reportés, fichier voisin, dernière vérification (`etat.js`), faits du moment et temps écoulé (`faits.js`, D74), dossier de jeu posé ou remis à son départ (`jeu.js`, D75), variables de la page lues dans les couches communes, sans marque (`jetons.js`), page sans script (`page.js`), gabarit des écrans, lancement, écran des pages, mesure en cours, dette, marque, écriture des jetons et fondations (`ecrans.js`, D77 à D83), chiffres et phrases de la dette, calculés depuis la mesure et l'audit (`dette.js`, D79), marque lue dans l'audit par une règle et son aperçu par la saisie, sans rien écrire (`marque.js`, D80), fondations d'une marque saisie, calculées dans ses jetons écrits et ses paires jugées dans chaque contexte (`fondations.js`, D83), pages retirées, ajoutées après vérification, validées, et leurs vignettes, la dette vue, la marque changée et confirmée, les fondations vues (`pages.js`, D77 à D83), serveur sur 127.0.0.1 qui recalcule la page à chaque demande, sert les écrans de la même origine, reçoit les formulaires de l'écran des pages et prend un port libre si le sien est pris (`serveur.js`) |

## Fonctions communes

Une règle écrite à plusieurs endroits a une seule définition ; chaque lecteur l'importe.

| Règle | Définition | Lue par |
|---|---|---|
| Nombre à la française, texte échappé pour le HTML, arrondi à 4 décimales | `fr`, `esc`, `r4` dans `src/lib/format.js` ; chaque sortie nomme son format par les options de `fr` (D22) | consoles des contrôles et de la saisie, planches, revue, migration, calibrage, rapports d'audit, générateur |
| Contraste WCAG | `contrastRatio` dans `src/lib/color.js` ; culori n'en calcule plus dans `src/`, il reste l'oracle des tests (D22) | reduce, revue, migration, rapports d'audit, jetons, générateur, calibrage |
| Résolution d'alias DTCG | `resoudreAlias` dans `src/tokens/roles.js`, à côté de `flattenTokens` (D23) | rôles de couleur, espacements, typo |
| Valeur retenue après décision | `retenue` dans `src/reduce/propose.js`, à côté de `decisionFor` (D21) | simulation, conflits de déclarations, contrôle de proximité, migration, revue |
| Marques et leur nom | `dossiersDeMarque` et `nomDeMarque` dans `src/tokens/resolver.js` : chaque dossier de `tokens/` qui a un `marque.resolver.json`, et le champ `name` de ce resolver (D26) | les trois contrôles de la cible sans `--marque`, les planches |
| Échelles écrites à la main d'une marque | `echellesPropres` dans `src/tokens/saisie.js` : `primitives.tokens.json` du dossier, ou rien (D25) | saisie, calibrage |
| Aucune échelle commune redéfinie par une marque | `echellesCommunesRedefinies` et `motifRedefinies` dans `src/tokens/saisie.js` (D25) | saisie (refus), `npm run contraste` (échec) |
| Fusion de contexte d'une marque | `rolesDuResolver` dans `src/tokens/roles.js` : le resolver de la marque, résolu dans un contexte ; la saisie lui donne ses fichiers en mémoire (`enLigne`, `src/tokens/resolver.js`, D31) | `loadRoles` (contrôles, planches), saisie et son contrôle final |
| Texte du contrôle de contraste | `lignesContraste` dans `src/report/contraste.js` (D31) | `npm run contraste`, saisie |
| Consigne pour un agent | `consigneAgent` dans `src/report/consigne.js` : sections en listes d'entrées, consigne réduite de `reste.md` à côté (D29) | `migration.md` (texte), `modifications.json` (entrées) |
| Valeur après la table d'une couleur, par usage | `mapped` dans `src/reduce/pleins.js` (D30) | cartes de plein, couplages, migration |
| Liste de polices DTCG écrite en CSS (`font-family`) | `famille` dans `src/lib/format.js` : un nom avec une espace entre guillemets (D41) | planche de la typo, thèmes Vuetify |
| Lecture d'un fichier JSON | `lireJson` dans `src/lib/fichiers.js` : message qui nomme le fichier (absent, dossier, JSON illisible) (D30) | commandes, `runReduce` |
| Lancement de Chromium | `lancerChromium` dans `src/browser/lancement.js`, avec `--disable-partial-raster` (D34) | audit, reduce et `--live`, marque, verify, login, ajout, composants, contrôle d'encre de la saisie |
| Déclaration visée par une entrée de `modifications.json`, et garde de sa valeur écrite | `localiser` et `composantDe` dans `src/apply/localisation.js` : règle retrouvée par sa ligne et sa colonne quand l'entrée la donne (D38) | `npm run apply`, `npm run ajout` (D37) |
| Repères d'une déclaration que `table.json` ne garde pas (colonne, `!important` d'origine) | `reperesDe` et `cleRepere` dans `src/reduce/declarations.js` (D38) | `modifications.json` (`src/report/modifications.js`) |
| Ligne décidée arrivée à l'écran, et canal de ce qui n'arrive pas | `releverAvant`, `releverApres` et `juger` dans `src/verify/arrivee.js` : opérations de `scanInPage` (`src/browser/simulate.js`), la carte venant de `modifications.json` (D39) ; `feuilleDe` reconnaît ce que verify pose (`tokens.css`, feuilles ajoutées), `canalDe` dit ce qui tient la valeur et ce qu'il faut faire ; une cause par déclaration, celle du manifeste d'abord (D40) | `npm run verify -- … --ajout`, tests des feuilles ajoutées |
| Transitions et animations coupées le temps d'un relevé | `immobiliser` et `liberer` dans `src/browser/immobile.js` : feuille construite, adoptée puis retirée (D40) | états forcés de l'audit, `verify --ajout` |
| Version de Node d'une commande | `refus` et `garderVersion` dans `src/cli/version.js` : majeure de `.node-version`, sortie 2 sinon (D40) | chaque commande, par `lancer` ; `sombre`, `statuts` et `demo` directement |
| Ligne d'une clé de simulation (`famille\|ancienne\|usage\|relation`) | `ligneDeCle` dans `src/lib/cles.js` : la clé exacte, puis sans relation, puis sans usage (D39) | pages des lignes décidées (`src/report/modifications.js`), verdict (`src/verify/arrivee.js`) |
| Cause d'une ligne hors de `modifications.json` | `rester` dans `buildModifications` (`src/report/modifications.js`) : le texte du reste, inchangé pour `reste.md`, et sa cause juste pour `pertes.md` (D39) | `npm run apply`, `npm run ajout` |
| Règle qui gagne une propriété sur un élément | `winner` dans `src/browser/trace.js` | trace de l'audit et de reduce, règles gagnantes des feuilles ajoutées (`src/browser/ordre.js`) |
| Nom d'une variable CSS de jeton | `cssVar` dans `src/lib/nom-css.js` : chemin du jeton, points remplacés par des tirets ; `cssVarFallback`, la même variable lue avec l'ancienne valeur en repli (D62) | `tokens.css` de `npm run apply`, feuille de `npm run css` (D36), consigne et modifications, planches des espacements et des styles de texte |
| Textes affichés du constat des composants | `TEXTES` dans `src/report/textes.js`, lu dans `src/report/constat.textes.json` : étiquettes d'origine, états des blocs, explications des quatre scores, définitions, guidage, limites, mot pour mot les attendus (D46, D47) | `src/composants/pieces.js`, `src/composants/constat.js`, `src/composants/guidage.js`, `src/report/constat.js` |
| Nom stable d'une version de composant | `nomDeVersion` dans `src/composants/pieces.js` : « <type> / <origine> / <nom> » (D46) | versions relevées, blocs rattachés (`src/composants/constat.js`) |
| Jetons de `--tokens` | `jetonsDe` dans `src/tokens/resolver.js` : un resolver est résolu dans ses contextes par défaut, un fichier de jetons est lu tel quel (D28) | `npm run reduce` |

Un nouveau module de fonctions communes va dans `src/lib/` s'il ne dépend d'aucune couche ; sinon à côté de la fonction dont la règle dépend, comme `retenue` à côté de `decisionFor`. `test/format.test.js` et `test/contraste-source.test.js` vérifient qu'aucune copie ne revient.

Aucune branche de code ne dépend du nom d'une marque : une différence réelle entre marques vit dans les données de la marque (un fichier de son dossier, un champ de son resolver), pas dans `src/` (D25, D26 ; `test/marque-en-dur.test.js`).

## Invariants

Chacun est tenu par le code ou par un test, cité.

- Deux lancements sur la même entrée et la même machine donnent les mêmes sorties, à l'octet et sans neutralisation : audit (`audit.json`, `rapport.md`, `rapport.html`), réduction (`revue.html`, `table.json`, `migration.md`, `modifications.json`), capture de `verify`, constat des composants (`releve.json`, `constat.json`, `constat.md`, `constat.html` et chaque capture, D46) ; Chromium n'est lancé que par `lancerChromium` (D34) (`test/determinisme.test.js`). Les feuilles d'une page sont rangées dans l'ordre de la cascade (D33 ; `test/feuilles-cascade.test.js`). Seuls la date (horodatage, injectable par `now`) et le nom du dossier de sortie changent d'un lancement à l'autre ; le port fait partie de l'adresse donnée. D'une machine à l'autre, dépendent encore du système, sans correction (D32) : la couleur de l'anneau de focus du navigateur dans `migration.md` et `table.json`, les captures de `revue.html` (tracé, lissage, polices de repli), les mesures qui suivent la mise en page (aucune différence observée sur les fixtures [F]), une référence de `npm run verify` prise sur une autre machine, et le nom des dossiers de sortie, en heure locale, quand `audit.json` date en UTC.
- Le constat des composants ne juge rien : aucune sortie 1 ; un élément du gabarit n'entre dans aucun chiffre ; le constat recalculé depuis `releve.json` sans navigateur est identique à l'octet à celui du lancement ; chiffres des pages d'annuaire égaux à l'attendu écrit à la main (`fixtures/marque-demo/expected-composants.json`), page HTML sans script ni requête, lisible à 390 px de large en clair et en sombre, couleurs égales aux rôles neutres communs, quatre explications (i), vignettes à la taille réelle de l'élément sauf dépassement, sans le mot « enveloppe » ; guidage égal à l'attendu écrit à la main (`fixtures/marque-demo/expected-forme-constat.json`) ; graphiques égaux au leur (`fixtures/marque-demo/expected-graphiques-constat.json`), chaque arc et chaque segment avec son texte de remplacement, aucune couleur hors des neutres et de la teinte d'information, chaque couleur d'origine à 3:1 contre la surface, aucune fiche ouverte au chargement (`test/e2e-composants.test.js`, `test/composants-guidage.test.js`, D47, D48) ; ses textes affichés sont ceux des attendus, mot pour mot (`test/composants-textes.test.js`, D46, D47).
- Le site audité n'est jamais modifié : les nouvelles valeurs sont posées dans le navigateur de l'outil, le temps des captures (`src/browser/simulate.js`).
- `npm run apply` ne remplace une déclaration que si la valeur écrite est celle attendue, sinon il la sort en écart ; relancé sur une copie migrée, il ne change rien (`test/apply-unit.test.js`).
- `npm run ajout` n'écrit aucun fichier du site ; deux générations sont identiques à l'octet ; il n'ajoute aucune spécificité, et `!important` seulement là où la déclaration d'origine l'a (D38) ; une ligne décidée est écrite dans sa feuille ajoutée ou listée dans `pertes.md`, sous sa cause (`test/ajout-unit.test.js`). ## Limites du code

- Trois fichiers de `src/` dépassent 1 000 lignes (`src/browser/simulate.js`, `src/reduce/propose.js`, `src/report/review.js`) ; pas de lint.
- La garde des noms de marque (`test/marque-en-dur.test.js`) est lexicale : elle interdit aussi le premier mot du dossier de chaque marque dans les chaînes de `src/`. Une marque dont le dossier commence par un mot courant le rend inutilisable : « maison » a fait réécrire une phrase du spécimen de la typo, et « atelier » reste interdit ; le générateur des fiches lit le nom de son dossier au lieu de l'écrire. Remède : reconnaître le nom complet ou des mots entiers.
- Copies restantes hors de `src/lib/` : `fr` du script de page de la revue (`src/report/review.js`, dans une chaîne) et `fr1` du contrôle d'encre (`src/polices/encre.js`) ; `plural` (2 copies) ; ΔE OKLab × 100 (sur culori et `deltaE`, écart au plus 9,4e-7) ; arrondi à 2 décimales (7 copies) et à 4 décimales écrit en ligne (7 endroits).
- L'agrégat d'audit calcule les `usages` de reduce pendant le relevé, élément par élément (`src/rendered/aggregate.js`) ; `sameColor` (`src/browser/trace.js`) relit les couleurs hex et rgb à la main au lieu de `src/lib/color.js`.
- Codé sans test :
  - le refus « fichier de police que le navigateur ne charge pas » (`PoliceRefusee`, `src/polices/encre.js`), faute d'un fichier qui passe les garde-fous et que Chromium rejette ;
  - le motif « non stabilisé après 10 tours » de la boucle de `propose` (`src/reduce/propose.js`), aucune entrée connue ne la faisant osciller ; la trace en panne dans un audit de bout en bout (testée au niveau de `measureRendered` seulement) ; les messages d'une navigation échouée de `reduce --live` et de `npm run login` ;
  - le refus « Terrazzo et le lecteur diffèrent » (`src/tokens/css.js`) : aucune marque connue ne le provoque sans modifier l'un des deux lecteurs ;
  - la saisie, quand la remise en place des fichiers d'origine tombe elle-même (D31, `src/tokens/ecriture.js`) : le message nomme les fichiers laissés en l'état [H].
